## What landed

### Harness (`src/aegir/ontology/deeponto_harness.py`)

- **JVM init pattern** (`ensure_jvm`) replicating gaius's
  click-prompt-avoiding pattern: `JVM_MEMORY` env var set
  before any `deeponto.onto` import.
- **System-library bootstrap** (`scripts/setup_jvm_env.sh`):
  surgical `LD_LIBRARY_PATH=/tmp/jvm-libs` exposing only
  `libz.so.1` (the system openjdk-11 dependency the nix
  devenv profile masks). Critical: a broader
  `LD_LIBRARY_PATH=/usr/lib/x86_64-linux-gnu` drags in a
  system libc that conflicts with the venv's nix-built
  numpy/torch wheels (GLIBC 2.38/2.39 mismatch — *uv* itself
  segfaults).
- **Template-to-OMN renderer** (`render_template_ontology`)
  emits Manchester-syntax ontology documents with placeholder
  filler IRIs and slot-marker labels. Markers use
  `ZZ<slot_name>ZZ` form — preserves case, survives spaCy
  tokenization, and reverses cleanly to `{<slot_name>}` in
  the verbal template via regex.
- **Auto-declaration** (`_auto_declare_referenced_iris`): emits
  Class / ObjectProperty stubs for any CURIE in the template
  body that isn't a slot. Heuristic Class-vs-Property
  classification by adjacency to restriction keywords (`some`,
  `only`, `min`, `max`, `exactly`).
- **Public-namespace label dictionary** (`PUBLIC_LABELS`):
  ships canonical labels for BFO 2020 numeric IRIs
  (`bfo:0000051` → "has part", etc.) and CCO upper structure.
  Without this, auto-declared classes fall back to local-name
  fragments ("0000051"), producing useless verbalizations.
- **Three-strategy verbalizer**
  (`_verbalize_for_template`): tries equivalence-axiom
  verbalize → complex-expression verbalize → subsumption-axiom
  verbalize over every axiom involving the head class;
  collects all successful candidates and returns the longest.
  Falls through gracefully on individual failures.
- **No manufactured fallbacks.** The first iteration included
  a hand-rolled cardinality verbalizer that produced
  "{X} has min 1 Y via p" for `ObjectMinCardinality`
  expressions DeepOnto doesn't support natively. **Removed**
  per direct feedback that fallbacks of that shape inject
  spurious signal into the downstream RL reward, degrading
  the verifier's discriminative validity. Cardinality
  templates that can't be verbalized are recorded with
  empty `verbal_template` and the failure cause in
  `provenance.deeponto_error`.

### Catalog construction (`scripts/build_catalog.py`)

- Reads candidate JSON, runs the harness template-by-template,
  populates `is_complex` / `verbal_template` /
  `mean_verbal_length`, writes augmented JSON.
- Per-template progress + summary stats (loaded /
  is_complex / verbalized rates / failure-kind histogram).
- `Justfile` recipe `just build-catalog input output`
  bootstraps the LD_LIBRARY_PATH automatically via the
  `setup_jvm_env.sh` helper.

### Batch 1 catalog (`src/aegir/ontology/catalog/01_foundation.json`)

**81 templates authored, 73 verbalized (90%), 68 is_complex (84%).**

| Family | Authored | Verbalized | Coverage |
|---|---|---|---|
| F1 — basic SubClassOf | 10 | 10 | 100% |
| F2 — existential restriction (`some`) | 34 | 34 | 100% |
| F3 — universal restriction (`only`) | 8 | 8 | 100% |
| F4 — cardinality (`min` / `max` / `exactly`) | 14 | 9 | 64% |
| F5 — equivalent-with-intersection (`and`) | 8 | 5 | 62% |
| F6 — equivalent-with-union (`or`) | 3 | 3 | 100% |
| F7 — negation (`not`) | 4 | 4 | 100% |

**The 90% verbalization rate exceeds the brief's R_C threshold
of 80%.** Every axiom family appears ≥3 times per the kickoff
plan's commitment.

The 8 unverbalizable templates are honest DeepOnto verbaliser
limitations:

- 5 pure `ObjectMinCardinality` / `ObjectMaxCardinality` /
  `ObjectExactCardinality` expressions — DeepOnto's
  `OntologyVerbaliser` raises "Input class expression … is not
  in one of the supported types" on these.
- 3 EquivalentTo-with-intersection-containing-restriction
  patterns (e.g., `{X} EquivalentTo: cco:DirectiveICE and
  (sdg:authoredBy some {Y:Class}) and (sdg:appliesTo some
  {Z:Class})`) — verbaliser declines to render.

These templates are retained in the catalog with empty
`verbal_template` and the failure recorded in
`provenance.deeponto_error_kind: "verbalize"`. Compositions
that include them score `R_C = 0` for those templates, which
is the correct downstream signal — no manufactured score
inflates them.

### SDG vocabulary TTL (`src/aegir/ontology/sdg-vocab.ttl`)

Publication-grade hardening. 28 SDG-namespace object
properties declared, each with `rdfs:label` and
`skos:definition`. Includes the `cco:DirectiveICE`
`owl:equivalentClass` bridge to `cco:ont00000965` (the
canonical CCO "Prescriptive Information Content Entity"
class) so the rename is shorthand-only and CCO-side deductions
remain available.

DeepOnto loads the TTL cleanly: 6 classes (CCO upper
structure consumed) + 28 object properties.

Future batches extend this TTL with their own branch-specific
classes (`sdg:LabRun`, `sdg:Trace`, `sdg:OutlierClaim`,
`sdg:eBPFProgram`, `sdg:KernelHook`, etc.) per the kickoff
plan in `docs/scratch/2026-05-09/235104_p1a_kickoff.md`.

## Engineering notes worth preserving

- **`deeponto>=0.9.0`** in `pyproject.toml` `[ontology]` extra. Run
  `VIRTUAL_ENV=$PWD/.devenv/state/venv uv pip install
  'deeponto>=0.9.0' 'jpype1>=1.5'` once to install (a full `uv
  sync --extra ontology` would also work but risks
  re-resolving CUDA wheels per CLAUDE.md's `--no-sync`
  discipline).
- **First-run download:** DeepOnto's verbaliser auto-downloads
  spaCy's `en_core_web_sm` model on first `OntologyVerbaliser`
  instantiation. ~12 MB; one-shot.
- **JVM init cost:** ~4-5 s amortized; per-template probe
  cost ~1 s on this hardware. Batch 1 (81 templates) ran in
  ~99 s wall clock.
- **Wall-clock at scale:** the kickoff plan's ~565-template
  total catalog should run in ~12-15 minutes at this rate —
  well within an unattended overnight slot.

## What's deliberately not done

- **No drop of unverbalizable templates.** All 81 stay in the
  catalog; the 8 verbalize-failures carry their failure cause
  in provenance and score R_C=0 at runtime. Dropping them would
  remove valid is_complex contributions to R_B and bias the
  catalog toward DeepOnto-friendly axiom shapes only.
- **No null-distribution generation.** That's P1b-β scope
  (BERTopic + Hungarian alignment + structural-shuffle null).
  Templates currently carry empty `null_stats`; the runtime
  verifier uses placeholder τ_B and L_target until P1b-β.
- **No per-template `description` field.** Template provenance
  carries `family` / `branch` / `remark` annotations; a
  `rdfs:label`-equivalent for templates themselves is deferred
  pending review of whether reviewers want per-template
  natural-language descriptions or the TTL's term-level
  labels suffice.
