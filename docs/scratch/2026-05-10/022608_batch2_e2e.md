## Engineering notes

- **Harness time scales linearly** with template count (~1.2 s
  per template after JVM startup amortized). At this rate, the
  remaining ~390 templates targeted by the kickoff plan would
  build in ~8 minutes — easily fits an unattended overnight.
- **No new manual fallbacks introduced.** Per the prior session's
  guidance, fallbacks that produce non-DeepOnto-derived
  verbalization are off the table since they would degrade the
  RL reward's discriminative validity. The single Batch 2
  failure is recorded honestly with its DeepOnto error in
  provenance.
- **eBPF templates work cleanly.** First batch with full eBPF
  branch coverage; the 7 templates in `ObservationProcess.eBPFEvent`
  all verbalize at 100% — the `auto_declare_referenced_iris`
  + `PUBLIC_LABELS` infrastructure handles the
  cybersec-specific properties (capturedBy, atHook, forSyscall,
  writesToMap, observesPid) without special casing.

## Path forward — P1b-β scoping

Per the user's prioritized plan, P1b-β (BERTopic + Hungarian
matching + null-distribution generation for R_D) is the next
engineering target now that Batch 2's verbalization content
provides a substantive corpus for topic modeling.

Estimated effort: 3–5 engineering days. Adds:

- `bertopic` + `sentence-transformers` to the runtime path
  (already a project dep, but currently used only by MMR
  context selection).
- A pinned input corpus *I* (held-out subset of v2's
  SchemaPile + FinePDFs-lab; ~200 MB).
- BERTopic fit on *I* once at P1b-β bring-up; cached to disk.
- Null-distribution generator: structural-shuffle compositions
  over the catalog, ~200 shuffles, cached as catalog metadata
  per [Charter §Mechanical checks](../../current/ontology/charter.md#mechanical-checks).
- Hungarian matching via `scipy.optimize.linear_sum_assignment`
  on c-TF-IDF representations.

Once R_D is wired, the full verifier *R(O, I)* becomes
operational and the AUC-tuning of {a, b, c} weights at P2 can
proceed. That unlocks claim C1 (verifier discrimination)
empirically.
